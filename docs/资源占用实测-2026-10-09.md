# 2026-10-09 资源占用实测

记录时间：2026-10-09T20:14:30+08:00。Apple M4、10 个逻辑核心、24 GiB 内存；macOS 本地开发运行的真实 Electron 客户端。本次仅测量与记录，没有修改业务实现、代理开关或节点配置。测量结束恢复“最近 2 分钟”视图。

## 方法与口径

通过 ps 每秒采集主进程与其子进程的累计 CPU 时间及 RSS，每组连续约 45 秒。平均 CPU = 组内累计 CPU 时间差 / 实际墙钟间隔；100% 表示一个逻辑核心满载，不是整台 10 核机器满载。RSS 为各进程驻留内存相加，共享页可能重复计入，不等于唯一物理内存或图表独占内存。统计包含 Electron 主进程、渲染、GPU、网络、统计工作进程和常驻内核；短暂 netstat/lsof 子进程用单独实验估计。

先测设备网络设置页，再测连接页；期间观察到客户端从设备网络变成代理流量。早期连接页数据因此不用于页面对照。最终对比重新在代理已连接状态下执行，连接页等待 5 秒再开始采集；各组起止原生 UI 均检查页面、历史范围和连接状态。没有主动制造下载负载或上传负载，真实后台流量随系统应用变化。

| 场景 | 时长 | 平均 CPU | 约 1 秒 CPU 峰值 | 平均 RSS 合计 | RSS 峰值 |

| 代理连接／连接页最近 2 分钟 | 45.72 秒 | 10.89% | 52.09% | 749.7 MiB | 777.6 MiB |
| 代理连接／连接页本次运行（约 36 分钟历史） | 45.91 秒 | 20.34% | 79.69% | 715.0 MiB | 731.3 MiB |

最近 2 分钟连接页中，渲染进程平均 CPU 8.20%，统计工作进程 0.15%；本次运行历史视图分别为 16.51% 和 0.28%。连接页还包含出口图和连接明细，所以页面差值不能全部归因于趋势图。历史范围切换使页面平均 CPU 从 10.89% 增至 20.34%，提示长历史处理和绘制值得优先分析，但这不是严格隔离单组件的基准实验。

RSS 随垃圾回收、共享页及历史驻留变化；本次运行组平均 RSS 低于最近 2 分钟组，不应据此推断长历史更省内存，也不能从短时数据断言内存泄漏。

## 系统读取单独实测

- 流量读取：相同 `/usr/sbin/netstat -ibn` 命令执行 20 次，全成功。平均墙钟 6.16 ms，最大 10.09 ms；平均子进程用户态加内核态 CPU 3.93 ms。按实际约每秒一次折算，约为单核 0.393%。这是未连接时设备流量读取路径的成本估计；代理连接后该读取路径停止，改读代理内核统计。
- 连接列表读取：相同 lsof 命令执行 10 次，全成功。平均墙钟 47.30 ms，最大 54.78 ms；平均 CPU 44.16 ms。按该服务约每 3 秒一次折算，约为单核 1.472%。它用于系统连接观察，不属于下载上传趋势采样；是否启用由连接需求和进程归属信息决定。
- 子进程 CPU 通过 Python RUSAGE_CHILDREN 前后差测得；读取输出只用于本地统计，未将连接地址、应用路径或节点凭据写入报告。

## 结论与限制

系统字节计数读取本身开销较小，没有主动测速流量。当前可见连接页的整体 CPU 开销明显高于设置页，尤其本次运行历史视图；主要增长在渲染进程，应优先分析图表重绘和历史数据处理。不能再笼统称整个趋势展示“负担很小”。

每组约 45 秒，客户端本次运行约 36 分钟；没有进行 24 小时上限测试、稳定可重复网络负载测试或生产构建对比，未测 Windows/Linux。CPU 峰值受 1 秒采样和 CPU 时间计数精度影响。这份结果只代表本机当前版本与负载，不能推广到所有硬件。
