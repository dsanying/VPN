# 企业 VPN 用户态引擎

企业网关通过普通“添加节点”自动识别，复用默认节点、节点列表和规则指定出口。智能分流开启后认证已保存的企业节点以读取网关资源；全局模式仅认证默认出口或生效的依赖节点。每个网关独立 Go 进程通过带随机认证的本机 SOCKS 桥接现有网络接管。全局开关关闭时统一回收，不建立第二套 TUN 或强制覆盖分流规则。OpenConnect 使用 script-tun 的数据报 socket，不安装第二套路由；aTrust / EasyConnect 使用固定版本 zju-connect 的协议实现。账号和密码只经 stdin 进入引擎，原始供应商日志不转发。配置保存在应用私有目录的 SQLite，使用应用持有的本地随机密钥做 AES-256-GCM 加密；不依赖钥匙串、DPAPI 或其他系统密码服务。数据库和密钥文件限制当前用户访问，界面不回读密码明文。

运行 `node scripts/build-enterprise-runtime.mjs` 构建本机引擎。脚本固定上游提交并应用 TLS 校验覆盖层：网关 HTTPS 会话强制 CA 校验，EasyConnect 登录证书获取后的传输钉扎该校验；厂商隧道面（aTrust SDP 节点、EasyConnect 握手）保留上游对齐官方客户端的自签设备证书语义，身份由内层认证握手承担。不能把上游默认值无条件覆盖到网关 API。输出完整源码归档及许可证。生成目录和用户配置均不提交。

本目录自有代码采用 AGPL-3.0-only，与 zju-connect 的授权一致；应用的其他模块仍按各自许可证分发。分发引擎时必须同时提供对应源码（含上游、修改和构建脚本）及许可证。OpenConnect 和依赖按各自许可证独立分发。

支持范围为桌面端：macOS arm64 打包自包含全部引擎（openconnect 及依赖库随包分发）；macOS x64 与 Windows 仅含纯 Go 运行时，对应 aTrust / EasyConnect，OpenConnect 系按引擎未安装如实拒绝；Android 不含企业引擎。OpenConnect 认证通过 libopenconnect 的结构化回调统一解析，支持初始表单只读发现、登录分组保存与运行时附加字段。网关协议解析使用上游实现，不自行猜测登录 POST。客户端证书、浏览器 SSO 与姿态准入不在支持范围。aTrust / EasyConnect 交互挑战经 IPC 返回界面，验证码与外部登录由用户完成。

Cisco AnyConnect 与 aTrust 已在真实网关完成端到端验证：表单/分组认证、OAuth2（ADFS）外部登录、用户态隧道与 SOCKS 桥接请求均通过（TLS 校验开启）；应用全局开关可正常启停。其余厂商仅依据上游协议支持与适配器契约接入，不凭厂商列表宣称真实网关兼容。

运行 `node scripts/test-openconnect-auth.mjs` 可离线验证表单发现、保存分组、交互响应、匿名 cookie 管道及拒绝无效证书。测试仅使用虚构网关、账密和 mock library；构建须先安装 OpenConnect/json-c 开发库。构建通过临时文件与原子替换，避免覆盖正在运行的已签名引擎。运行时脚本退出会主动关闭全局代理，不因外层 OpenConnect 尚存活而报告连接成功。

OpenConnect 数据报 socket 在突发压力下可能返回短暂 ENOBUFS。统一数据报传输层序列化完整包、有界重试队列压力，并支持关闭取消；不把未写入的包当作成功。内核路由对活动企业引擎及网关保持直连，避免自身回流。

企业节点与其他节点共用六小时观测周期、单次检测合并、指纹失效和 measurements.sqlite 缓存。入口使用绑定物理网络的 TCP 探测；可用性要求企业隧道内真实 HTTPS 请求且 TLS 校验通过，认证成功本身不写虚假成功。没有可靠的内网测速目标时代理延迟显示“不适配”，不使用入口延迟或公网地址代替。后台遇到交互认证停止并记录“未确认”，手动检测可完成认证。智能分流仅根据网关明确下发的域名及 IPv4 网段生成运行时规则，用户规则优先，不写入用户配置；拒绝全局路由、宽泛网段及推测的企业域名。OpenConnect 环境字段依据[上游实现](https://gitlab.com/openconnect/openconnect/-/blob/master/script.c)。

当前隧道的六小时复测经本机认证的只读健康接口重新执行 HTTPS 转发，不重新认证或中断流量。每个适配器另提供本机 DNS 桥接，复用隧道解析器和网关静态资源映射；默认出口、指定应用和自动资源域名的 DNS 均随对应节点，避免内网域名泄漏至公网 DNS。隧道复测与 DNS 桥接均按真实连接核验；内网站点权限随网关策略而定。

### 统一节点检测与地区

入口延迟、认证隧道可用性、网关 IP 地区和支持协议的真实出口地区进入同一次 `runSpeedTest`，保存在同一个 `measurements.sqlite` 节点记录；沿用共享六小时有效期、初始化、配置指纹失效及后台调度，不新增企业专用地区定时器。网关地区查询使用入口探测解析出的公网 IP，最多四个并发；同一检测批次按 IP 合并，HTTPS 查询 ipwho.is，失败再查 ipapi.co，单渠道 2.5 秒超时，禁止提交私网、FakeIP、域名或凭据。IP 地理数据库结果是归属地区参考，不代表隧道实际出口。

展示优先真实出口地区，否则显示网关地区；图标说明区分来源、IP、服务和观测时间，原生菜单标注“网关地区”。查询失败不改变节点可用性；同一网关 IP 的旧地区仅作为历史记录保留，IP 变化不借用旧地区。企业内网探测无公认可信目标时代理延迟显示“不适配”。

完整协议与认证覆盖范围见 [兼容依据](COMPATIBILITY.md)。aTrust 支持无凭据认证方式发现、登录域选择与密码/CAS/OAuth2/短信运行时接线；多个认证方式交由用户选择，唯一方式自动保存。旧配置缺少选择时走统一交互，后台检测不盲试密码。浏览器回调必须属于原网关 HTTPS origin；不同网关、端口、路径或缺少认证参数的回调被拒绝。SSO 浏览器自动捕获、客户端证书与跨平台企业隧道不在支持范围，明细见兼容表。

源码覆盖测试保留全部认证和 TLS 断言：测试服务仅信任夹具自己的 CA，生产会话拒绝不可信证书。固定上游的 session.request 会覆盖 Refresh(ctx) 的取消信号，构建覆盖层已合并调用方与会话上下文，并在响应体关闭后释放；取消测试及上游 aTrust/EasyConnect/挑战测试通过。上游失效的测试接口同步修正，未跳过失败测试。
